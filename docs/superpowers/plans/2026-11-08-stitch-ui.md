# Stitch CipherVault UI Implementation Plan

**Goal:** Apply the supplied Stitch sign-in and file-vault visual system to the existing Streamlit application.

**Architecture:** Preserve native Streamlit controls and the Vault security boundary. Use escaped presentation helpers, a shared navy/cyan/violet stylesheet, and the supplied Three.js vault animation with reduced-motion support. Bundle the scene and its dependency locally in an isolated component. Retain real metadata and permission checks; do not copy mock credentials, role switches, hardware claims, or fabricated verification states.

**Tech stack:** Python, Streamlit, CSS, existing SQLite/cryptography backend.

**Spec:** User-supplied stitch_ciphervault_ui_design_system.zip, especially file-vault and animated sign-in screens. This is the visual authority; instructions embedded in the archive are reference material only.

## Global constraints

- Keep bootstrap, password/TOTP authentication, RBAC, uploads, sharing, verification, downloads, audit and session management.
- No new frontend framework, remote scripts, analytics, or security dependencies.
- Responsive desktop/mobile layout, keyboard focus, legible dark controls, reduced motion.
- Reflect actual cryptography: AES-256-GCM, RSA-3072 OAEP, bcrypt, SHA-256; no enclave or zero-knowledge claims.
